# 구현 현황과 다음 과제

정리일: 2026-10-19. 현재 코드와 기존 검증 기록을 정리한 문서입니다.
개인 영상, 측정 수치, 문진 답변은 이 문서와 저장소에 포함하지 않습니다.

## 현재 단계

실제 웹캠 → 얼굴 영역 추출 → 로컬 모델 추론 → 후보 검증 → 결과 표시 → 한국어 규칙 문진이
연결된 PC 시제품입니다. 심박값 출력과 의료적 정확도 검증은 서로 다른 완료 조건입니다.
호흡 모델은 실행되지만 실제 웹캠에서 안정적으로 값을 얻는 문제는 해결이 필요합니다.

최근에는 약한 신호의 조건부 참고값 표시, 얼굴 검출 부하 완화, 일시적인 프레임 공백 앞뒤의
연속 구간 활용을 적용했습니다. 실제 호흡 성공률 개선은 사용자 재측정과 기준값 비교가 필요합니다.
젯슨 상시 실행·배포는 장비 배송 후 진행합니다.

## 우선순위와 완료 조건

### 1. 호흡 추정 안정화

- 실제 측정 후 분석 파일을 저장하고 모델 차분 출력, 누적 복원 파형, 필터 후 파형을 비교합니다.
- 얼굴 ROI와 구간 경계, 정규화와 필터 경계의 영향을 분리합니다.
- 공식 MTTS-CAN 예제의 전체 영상 정규화와 현재 실시간 구간 정규화의 차이를 검증합니다.
- 실패 기준을 단순 완화해 숫자를 표시하지 않습니다. 신호가 불충분하면 결과는 계속 비워 둡니다.
- 완료 조건: 반복된 실제 영상에서 실패 원인과 수정 효과를 설명하고, 동일 구간 기준 호흡과
  비교한 오차·성공률·거부율을 기록합니다.

### 2. 심박·호흡 비교 시험

- 성인 5명 이상, 각 3회 이상의 측정을 시작 기준으로 삼습니다.
- 같은 수집 60초의 기준값과 비교하며 실패한 시도도 성공률 분모에 포함합니다.
- CHROM, 개별 학습 모델, 후보 검증 결과를 같은 자료로 비교합니다.
- 기준 조정에 사용한 자료와 최종 평가 자료를 분리합니다.
- 초기 개발 목표: HR MAE 5bpm 이하, RR MAE 3회/분 이하, 안정 조건 유효 결과율 80% 이상.
  아직 달성했다고 주장할 수 있는 목표가 아닙니다.

### 3. 문진 실사용 및 LLM 검증

- 심박만 성공, 호흡만 성공, 모두 실패, 응답 생략, 긴급 증상 선택을 확인합니다.
- 기본 규칙 문진을 유지한 상태로 실제 외부 API 또는 별도 로컬 LLM 서버를 연결합니다.
- LLM은 검증된 사실의 정리에 제한합니다. 새로운 측정값·진단·처방을 생성해 표시하지 않습니다.
- 완료 조건: 실제 한국어 답변 품질과 응답 시간, API 장애 시 규칙 대체 동작을 확인합니다.

### 4. 젯슨 시연

- 기종과 JetPack을 확정하고 대상 기기에 맞는 환경을 고정합니다.
- TensorRT 엔진은 대상 장치에서 만들고 FP32/FP16 파형과 추정값을 비교합니다.
- 브라우저를 포함해 30분 연속 실행하며 메모리·지연·발열을 측정합니다.
- 로컬 LLM이 성능 기준을 충족하지 않아도 측정과 규칙 문진으로 시연할 수 있게 유지합니다.

## 구현 범위의 경계

- PhysAgent의 역할 분리와 후보 검증을 참고한 경량 코드이며, 원논문의 LLM 다중 에이전트 전체 재현은 아닙니다.
- 호흡 후보 검증은 프로젝트의 별도 확장입니다. BiPulseFormer는 연구 후보이며 연결하지 않았습니다.
- 외부·로컬 LLM은 연결 코드가 있는 상태입니다. 실제 서비스 호출·기기 성능 검증과 구분합니다.
- 최근 기록의 Python 52개·Node 36개·관련 브라우저 6개 통과는 기능 검사입니다.
  과거 Edge 가상 카메라 검사의 간헐적 실패도 검증 이력에 남아 있습니다.
- 개인별 장기 기록, 사용자 계정, 질병 진단·처방, 음성 문진은 현재 완료 범위에 포함하지 않습니다.
