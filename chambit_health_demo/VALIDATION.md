# 측정 기능 검증 기록

## 2026-10-22 · 호흡 입력 길이 부족 시 제한된 추가 수집

- 실제 측정 분석에서 심박 최소 구간은 충족하지만 호흡 최소 35초보다 연속 구간이 짧아
  파형 품질 검사 전에 호흡 후보가 탈락하는 경로를 확인했습니다. 개인 측정 파일은 공개하지 않습니다.
- 준비된 호흡 모델이 있을 때 기본 60초 이후 최대 30초 추가 수집합니다. 실제 24fps 이상·
  100ms 이하 공백의 연속 35초를 확보하면 즉시 종료하며, 전체 시도 120초와 취소·재측정을 유지합니다.
  낮은 fps나 반복 공백 때문에 조건을 충족하지 못해도 무한히 연장하지 않습니다.
- 최근 60초 순환 버퍼를 유지하고, 분석 구간이 그대로인 모델 출력은 재사용합니다.
  이동한 버퍼에서 만료된 정규화 구간의 캐시만 폐기합니다. 추가 수집 중 심박·호흡 요청 주기는 각각 5초입니다.
- 프레임 공백과 연속 구간, 실제 수집 시간과 분석 버퍼 길이를 JSON에 별도로 기록합니다.
  Python 71개, Node 42개 검사 통과: 추가 수집 상한, 전체 시간 제한, 초기화와 캐시 만료·재사용 검증.
  Chrome·Edge 관련 화면 검사 4개 통과: 추가 수집 안내, 완료 표시 보류, 최종 결과 및 재측정 확인.
- 합성 영상·공식 가중치 성능 검사에서 66.9초에 필요한 연속 구간을 확보했습니다. 추가 수집 중
  새 구간 첫 추론은 약 4.61초, 후속 추론은 약 0.63초, 최종 추론은 약 0.92초였습니다.
  이는 한 번의 로컬 처리 성능 확인이며 실제 카메라 성공률이나 호흡 정확도 근거가 아닙니다.

## 2026-10-19 · 일시적인 프레임 공백 이후 호흡 분석 복구

- 사용자에게 최근 표시된 영상 끊김·전달 속도 부족 안내를 기준으로 입력 구간 처리를 수정했습니다.
  기존에는 100ms 초과 공백 하나로 학습 모델의 전체 구간을 거부했습니다. 이제 공백을 기준으로
  나눈 연속 구간 중 실제 24fps 이상이며 가장 긴 구간 하나를 사용합니다. 긴 공백 보간이나
  서로 떨어진 구간 연결은 하지 않으며 호흡 최소 35초와 신호 품질 조건은 유지합니다.
- 사용 구간이 줄어든 결과는 partialWindow와 실제 시각을 보존하고 화면·문진에서 안내합니다.
  60초 수집 중간의 약 0.17초 공백 뒤 연속 43초로 합성 호흡 출력을 복구하는 회귀 검사를 추가했습니다.
  양쪽 구간이 모두 35초 미만인 경우, 평탄 신호, 실제 낮은 fps, 재측정 초기화를 함께 검사합니다.
- MediaPipe 좌표만 60ms 미만으로 재사용합니다. 피부색과 모델 입력은 현재 실제 프레임을 읽습니다.
  얼굴 소실·여러 얼굴·재측정 시 이전 좌표를 유지하지 않는 동작을 검사했습니다.
- Python 63개, Node 41개 통과. 실제 사람의 웹캠 성공률·정확도 향상은 아직 검증하지 않았습니다.
- Chrome·Edge 관련 화면 검사 4개 통과. 호흡 실패 유지, 일부 구간 추정 안내의 카드·최종 화면 표시,
  실제 사용 시각과 참고값 상태의 JSON 보존을 확인했습니다. 화면 검사는 모의 응답을 사용합니다.
- 공식 MTTS-CAN 전체 영상 정규화와 현재 6초 구간 정규화의 차이도 확인했지만, 최근 안내와
  직접 관련된 입력 연속성 문제를 우선 수정했습니다. 정규화 변경과 비교 실험은 남은 과제입니다.

## 2026-10-19 · 촬영 조건 완화와 약한 신호의 참고값 표시

- 얼굴 이동·크기 변화 허용 범위와 ROI의 유효 노출 픽셀 비율을 완화했습니다.
  얼굴 이탈, 큰 움직임, 최소 픽셀 수, 원래 프레임 시각 및 학습 모델 입력 속도 조건은 유지합니다.
- 기본 balanced 모드에서 집중도 0.40, 반복성 HR 0.35 / RR 0.20 이상인 약한 파형은
  앞·뒤 절반 및 전체 구간의 추정값 범위를 검사합니다. HR 5bpm / RR 3회/분 이내일 때만
  tentative 상태로 표시하고, 기존 strict 기준을 통과한 후보가 있으면 그것을 우선합니다.
- 참고값 경고는 측정 카드·최종 화면·문진·JSON에 유지합니다. LLM이 해당 경고를 선택하지 않아도
  요약에 포함됩니다. `.env`의 SIGNAL_QUALITY_MODE=strict로 기존 파형 판정에 복귀할 수 있습니다.
- 합성 약한 호흡 신호가 참고값으로 표시되는 것과 평탄·비유한·짧은 구간·대역 경계·주파수 변화의
  거부를 확인합니다. 30개 고정 시드 백색잡음의 HR/RR에서는 완화로 추가된 표시값이 없었습니다.
  기존 strict 모드에서도 이 잡음 중 호흡 1건은 통과하므로 잡음의 완전한 거부를 주장하지 않습니다.
- 실제 웹캠 성공률·정확도 개선은 아직 검증하지 않았습니다. 같은 시간의 기준 심박·호흡과
  비교하고 성공률뿐 아니라 잘못된 참고값이 늘어나는지도 확인해야 합니다.
- Python 58개, Node 39개 통과. Chrome·Edge 관련 화면 검사 6개 통과: 부분 결과,
  참고값의 타임라인·최종 상태·문진 표시·JSON 보존, 명시적 데모 완료와 재시작을 확인했습니다.
  데모 검사의 가상 시계를 고정하고 분석 갱신 간격을 반영해 실행 환경의 시간 지연에 따른
  경계 시점 실패를 수정했습니다. 브라우저 전체 검사와 실제 카메라 검사를 대신하지 않습니다.

## 2026-09-14 · 호흡 탈락 근거와 분석 파형 저장

  경계 조건에 실제 값과 기준, 탈락 코드를 기록합니다. 모든 후보에서 반복성 조건이 부족하면
  일반 화면에 영상에서 반복되는 변화를 찾지 못했다는 안내를 표시합니다.
- 최종 결과에만 후보별 전체 입력·필터 후 파형, 학습 모델 차분 출력과 구간 정보를 포함합니다.
  사용자가 개발용 상세 정보에서 JSON을 직접 내려받습니다. 얼굴 영상·픽셀·문진은 제외하고,
  재측정·초기화 후에는 이전 결과의 내려받기를 비활성화합니다. 가상 데이터도 제외합니다.
- 신호 품질 임계값과 최종 수치 계산은 유지합니다. 실패 후보의 스펙트럼 피크는 분석 근거일 뿐
  유효한 심박·호흡수로 승격하지 않습니다. 합성 주파수 변화 파형의 거부, 실패한 모델 파형 보존,
  중간 결과의 전체 파형 제외, 유한 JSON 직렬화와 차분 복원을 검사했습니다.
- Python 52개, Node 36개 통과. 실제 사용자 정확도 검증을 대신하는 결과는 아닙니다.
- Chrome·Edge 관련 화면 검사 6개 통과: 명시적 데모 문진, 호흡 실패를 유지한 부분 결과,
  실제 JSON 내려받기·영상/문진 제외·재측정 초기화·분석 시작 타임라인을 검증했습니다.
- 이번 변경은 실패 원인을 더 자세히 확인하는 기능입니다. 실시간 호흡 성공률 개선이나
  기준 기기 대비 심박 오차 개선이 확인된 상태는 아닙니다. 개인 측정 기록은 저장소에 포함하지 않습니다.

## 2026-09-14 · 프레임 수집 병목 수정

- 사용자 화면에서는 얼굴 ROI가 표시됐으나 60초 후 심박·호흡 모두 영상 속도 부족으로 거부됐습니다.
  당시 실제 fps·처리 시간은 확보되지 않아 특정 장치나 촬영 환경이 원인이라고 단정하지 않습니다.
- 카메라의 최대 30fps 요청 뒤 프레임 간격을 중복 제한하던 로직을 제거했습니다. 얼굴 처리 중에는
  최신 실제 프레임 하나만 대기시켜 처리 완료 즉시 전달합니다. 이전 대기 프레임은 해제하고,
  촬영 시각·중복 프레임 거부·취소 및 구간 변경 처리를 유지합니다.
- 화면 상태 갱신은 최대 약 4회/초, ROI 테두리는 최대 약 10회/초로 줄였습니다.
  모델 출력이 캐시된 과거 구간은 다시 축소하지 않고 새 입력 구간만 전처리합니다.
- `capture` 진단에 브라우저 영상 표시 fps, 콜백 fps, 얼굴 처리 fps·시간, 대기 교체,
  얼굴 조건 거부, 전송 누락을 구분했습니다. 속도 부족 안내는 측정 도중에도 표시합니다.
  클라이언트 진단은 설명용이며 서버의 실제 시각 기반 입력 검증을 우회하지 않습니다.
- Python 48개·Node 35개 통과. 30fps 입력과 38ms 처리 시간을 가정한 모의 실행에서 24fps 이상
  전달, 촬영 시각 유지, 대기 프레임 해제, 취소 후 늦은 비트맵 폐기를 확인했습니다.
  36초 캐시 뒤 38초 분석에서 전체 1,141프레임 대신 새 구간 64프레임 이하만 축소했습니다.
- 브라우저 전체 검사 15개 통과, Edge 가상 카메라 연결 종료 1개 실패(단독 재실행도 실패).
  별도 Edge 확인에서는 최대 30fps 설정으로 실제 Worker가 동작했으며 가상 장치의 영상 속도는
  20fps였습니다. 가상 장치 종료는 두 요청 설정에서 관찰돼 검사의 불안정성을 별도로 남깁니다.
  이는 실제 사용자의 카메라 성능이나 수정 후 측정 성공을 입증한 결과가 아닙니다.
- 속도 안내·진행 막대·재측정 초기화의 후속 Chrome·Edge 검사 2개는 통과했습니다.

## 실제 사람 비교 시험 — 미수행

사람의 웹캠 영상과 동시 기준 심박수·호흡수가 확보되지 않아 실제 사람 대상 정확도와 측정 성공률은 아직 산출하지 않았다. 아래 절차로 후속 검증한다.

1. 같은 카메라·브라우저를 사용해 편안한 앉은 자세와 고른 조명에서 측정한다. 브라우저·카메라·조명 조건을 기록한다.
2. 준비 5초를 제외한 **동일한 수집 60초** 동안 기준 기기의 평균 심박수와 관찰자가 센 호흡 횟수를 기록한다. 특정 시점의 기기 표시값을 60초 평균 대신 비교하지 않는다.
3. 독립된 측정을 최소 3회 진행하고 앱의 원래 결과를 그대로 기록한다. 측정 불가 시도도 성공률 분모에 포함한다. 반복된 중간 추정값을 독립 측정으로 세지 않는다.
4. 심박·호흡별 절대 오차와 평균 절대 오차, 유효 결과 수/전체 시도 수를 계산한다. 기준 장비의 종류·한계도 함께 적는다.
5. 움직임·조명 변화·낮은 fps 조건에서는 수치 정확도와 별도로 거부/재준비가 의도대로 일어나는지 확인한다. 서로 다른 피부색·얼굴 가림·카메라 조건에 대한 일반화는 이 소규모 시험만으로 주장하지 않는다.
